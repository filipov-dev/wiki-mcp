# MCP-инструменты

Каждая операция Wiki API из встроенной спецификации — отдельный MCP-инструмент. Спецификация — официальная OpenAPI-спецификация Wiki API с дополнением: короткие имена операций, уровни доступа, наборы, русские описания из [справочника Wiki API](https://yandex.ru/support/wiki/ru/api-ref/) и исправления расхождений с реальным API ([описание спецификации](../crates/wiki-api/spec/README.md)). Это 57 операций в шести наборах: 47 из справочника и 10, которые есть только в официальной спецификации. Описание инструмента заканчивается ссылкой на страницу справочника.

Кроме операций есть составные инструменты `upload_attachment` (загрузка файла вложением страницы), `wait_for_operation` (ожидание фоновой операции) и `create_upload_url` (одноразовый адрес для загрузки файла, только в HTTP-режиме), всегда доступные `api_search` и `api_request` и [пользовательские инструменты](#пользовательские-инструменты) из `tools.toml`. Ответы инструментов можно сокращать [фильтром `jq`](#фильтр-ответа-jq).

Какие инструменты видит агент, задают уровень доступа (`--allow-write`, `--allow-destructive`) и наборы (`--toolsets`) сервера:

| | Наборы по умолчанию | `--toolsets all` |
| --- | --- | --- |
| Только чтение (по умолчанию) | 20 | 27 |
| `--allow-write` | 41 | 51 |
| `--allow-destructive` | 47 | 61 |

В числах учтены составные инструменты, `api_search` и `api_request`; [пользовательские инструменты](#пользовательские-инструменты) добавляются к ним. С [`--dynamic-toolsets`](#динамические-наборы) при запуске видно только пять служебных инструментов, остальное агент включает сам. В [HTTP-режиме](http.md#отличия-от-stdio) инструментов с локальными файлами нет, поэтому их меньше; зато с `--allow-write` там есть `create_upload_url`.

## Уровни доступа

По умолчанию сервер работает только на чтение. Инструменты выше разрешённого уровня не регистрируются: агент их не видит, а вызов по имени возвращает ошибку с флагом, который их включает.

| Уровень | Как включить | Инструменты |
| --- | --- | --- |
| read-only | по умолчанию | только чтение, в том числе поиск (`POST /v1/search`) и проверка slug столбца таблицы |
| write | `--allow-write` | плюс создание и изменение: страницы, комментарии, таблицы, вложения и сессии загрузки, копирование, перенос и восстановление страниц |
| destructive | `--allow-destructive` | плюс удаление (страниц, вложений, комментариев, таблиц, строк и столбцов) и изменение персональных прав доступа к страницам (набор `access`) |

Уровень по HTTP-методу не определить: в Wiki API `POST` означает и поиск, и правку, а изменение прав доступа через `POST` — уровень удаления. Поэтому уровень каждой операции задан в спецификации (`x-access-level`).

У каждого инструмента есть аннотации MCP: `readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint` и `title`.

Флаги командной строки важнее настроек профиля ([`serve`](cli.md#уровни-доступа-и-наборы)). Уровень доступа сервера не расширяет права токена: Wiki всё равно проверяет права пользователя и [права OAuth-приложения](oauth.md#права-приложения).

## Наборы инструментов

Без `--toolsets` и без настройки профиля включены `pages`, `attachments`, `comments` и `grids`. `--toolsets all` включает все наборы. Неизвестный набор — ошибка запуска со списком допустимых.

| Набор | Что внутри | По умолчанию |
| --- | --- | --- |
| `pages` | Страницы: чтение, создание, правка, удаление и восстановление, копирование, подстраницы, поиск, текущий пользователь | да |
| `attachments` | Вложения страниц и сессии загрузки файлов | да |
| `comments` | Комментарии к страницам | да |
| `grids` | Динамические таблицы | да |
| `access` | Персональные права доступа к страницам | |
| `extra` | Операции из официальной спецификации, которых нет в справочнике Wiki API | |

Составные инструменты входят в наборы: `upload_attachment` — в `attachments`, `wait_for_operation` — в `pages`.

### Динамические наборы

Клиенты, которые не откладывают загрузку инструментов, кладут описания всех зарегистрированных инструментов в контекст модели сразу. С флагом `serve --dynamic-toolsets` сервер при запуске регистрирует только:

- `api_search` и `api_request` — как обычно;
- [пользовательские инструменты](#пользовательские-инструменты) из `tools.toml` — их настроил пользователь, поэтому они регистрируются сразу и не входят ни в один набор;
- `list_toolsets` — наборы с описанием, инструментами, доступными на текущем уровне (вместе с составными), примерами имён, числом операций выше уровня доступа (`above_access_level`), признаками `default` и `enabled`;
- `enable_toolset` — включить набор (аргумент `toolset`, можно несколько через запятую или `all`). Ответ перечисляет добавленные инструменты;
- `disable_toolset` — выключить набор, чтобы снова сократить список.

`--toolsets` вместе с `--dynamic-toolsets` задаёт наборы, включённые при запуске; без него при запуске не включено ни одного набора (наборы профиля в этом режиме тоже действуют как наборы при запуске). После `enable_toolset` и `disable_toolset` сервер отправляет клиенту `notifications/tools/list_changed` (в инициализации объявлена возможность `tools.listChanged`): в сессии с `initialize` — сразу после вызова, в протоколе MCP 2026-07-28 — по подписке `subscriptions/listen`. Клиент перечитывает `tools/list` и видит новые инструменты.

Уровень доступа действует как обычно: `enable_toolset` не регистрирует инструменты выше разрешённого уровня. Составные инструменты включаются вместе со своим набором: `wait_for_operation` — с `pages`, `upload_attachment` — с `attachments` при `--allow-write`. Включённые инструменты — те же, что без `--dynamic-toolsets`, и тоже принимают [фильтр `jq`](#фильтр-ответа-jq). Сами инструменты управления наборами — уровня чтения: они меняют только список инструментов сервера, а не данные Wiki, и к API не обращаются. Если клиент не перечитывает список инструментов, агент может вызвать ту же операцию через `api_request` (метод и путь подскажет `api_search`); у составных инструментов такой замены нет.

Динамические наборы работают только в stdio: HTTP-сервер ([HTTP-режим](http.md)) не хранит сессий, поэтому `--dynamic-toolsets` вместе с `--http` — ошибка запуска. Состояние наборов принадлежит сессии: после перезапуска сервера включены снова только наборы из `--toolsets` или профиля.

## Частые задачи

| Задача | Инструменты | Уровень |
| --- | --- | --- |
| Прочитать страницу с текстом | `get_page` (`slug`, `fields: "content"`) или `get_page_by_id` (`idx`) | чтение |
| Обойти дерево страниц | `list_page_descendants` (`slug`) или `list_page_descendants_by_id` (`idx`), затем `cursor` из `next_cursor` | чтение |
| Найти страницу по словам | `search` (`body: {"query": "…"}`) | чтение |
| Создать страницу под родителем | `create_page` с полным `slug` от корня (`team/project/new-page`) | запись |
| Заменить текст страницы | `get_page_by_id` с `fields: "content"`, затем `update_page` (`body: {"content": "…", "revision": "…"}`) | запись |
| Дописать текст в начало, конец или раздел | `append_page_content` (`body: {"content": "…", "body": {"location": "bottom"}}` или `section`) | запись |
| Приложить файл и показать его на странице | `upload_attachment` (в HTTP-режиме — `create_upload_url` и `curl`), затем `append_page_content` с `{% file src="<download_url>" name="<имя>" %}` | запись |
| Скачать вложение | `list_attachments`, затем `download_attachment` (`save_to`) | чтение |
| Прокомментировать | `create_comment` (`body: {"body": "…"}`) | запись |
| Работать с таблицей | `list_page_grids`, `get_grid`, `add_grid_rows`, `update_grid_cells` | запись |
| Скопировать страницу и дождаться копии | `clone_page`, затем `wait_for_operation` | запись |
| Удалить и восстановить страницу | `delete_page` (сохраните `recovery_token`), `recover_page` | удаление и запись |

Если нужной операции нет среди зарегистрированных, агент находит её через `api_search`: в ответе сказано, какой флаг или набор её включает, а вызвать её в пределах уровня доступа можно через `api_request`.

## Аргументы и ответы

- Страница задаётся адресом `slug` — путём страницы от корня Wiki без домена (`team/project`; полный URL не подходит) — или числовым id `idx` (поле `id` из ответа `get_page`). Slug нужен полный, от корня: сокращённый путь даёт `404`.
- Параметры пути и строки запроса — аргументы с именами из API (`idx`, `slug`, `fields`, `page_size`); массив в строке запроса передаётся повторением ключа. JSON-тело запроса — аргумент `body`. Неизвестные аргументы и пропущенные обязательные — ошибка до отправки запроса. Поля внутри `body` схемой не ограничиваются: они уходят в Wiki как есть, проверяет их сам API.
- `fields` добавляет блоки ответа через запятую: `content` (текст страницы), `attributes`, `breadcrumbs`, `redirect`, `owner`, `access_policy`, `access_lists`, `actuality`; другое имя — ошибка 400. Без него страница приходит только с `id`, `slug`, `title` и `page_type`.
- Результат — JSON-ответ Wiki как есть.
- Ошибки Wiki (`4xx`, `5xx`) возвращаются агенту как ошибка инструмента (`isError: true`) с HTTP-статусом и телом ошибки (`error_code`, `debug_message`, `details`, `message`); сервер продолжает работать.
- Значения, похожие на учётные данные, заменяются на `[redacted]` во всех ответах, в том числе в ошибках; к результату добавляется пометка, что и сколько скрыто ([подробнее](security.md#учётные-данные-в-ответах)).

## Постраничная выдача

Списки Wiki API (подстраницы, вложения, комментарии) отдаются порциями: в теле ответа есть `next_cursor` (и `prev_cursor`). Следующую порцию агент получает тем же вызовом с `cursor`, равным `next_cursor`, пока он не станет пустым; размер порции — `page_size` (обычно до 100). Сервер ответ не оборачивает.

С [фильтром `jq`](#фильтр-ответа-jq) курсоры остаются рядом с результатом фильтра, в поле `pagination`.

Ответ больше `--max-response-bytes` (256 КиБ по умолчанию) не обрезается, а возвращается ошибкой с подсказкой сузить запрос: запросите меньше блоков `fields`, уменьшите `page_size`, уточните фильтр или оставьте нужное [фильтром `jq`](#фильтр-ответа-jq).

## Фильтр ответа jq

Ответы Wiki бывают большими: список подстраниц или страница с текстом быстро занимают контекст агента. Инструменты операций, `api_request` и [пользовательские инструменты](#пользовательские-инструменты) принимают необязательный аргумент `jq` — фильтр на языке [jq](https://jqlang.org/manual/) (диалект [jaq](https://github.com/01mf02/jaq)), который применяется к JSON-ответу до возврата агенту:

```json
{
  "slug": "team/project",
  "jq": ".results[] | {id, slug, title}"
}
```

- **Порядок обработки:** замена учётных данных на `[redacted]` → фильтр → лимит размера. Фильтр получает уже очищенный ответ, поэтому никакой фильтр (например, `.. | strings`) не раскрывает скрытые значения. Лимит `--max-response-bytes` применяется к результату фильтра; исходный ответ для фильтра читается до 16 МиБ. Результат больше лимита — ошибка с пометкой, что сам запрос выполнен.
- **Постраничная выдача.** Курсоры Wiki лежат в теле ответа, поэтому фильтр мог бы их потерять. Если в ответе-объекте есть `next_cursor` или `prev_cursor`, результат оборачивается: `{"result": <результат фильтра>, "pagination": {"next_cursor": …, "prev_cursor": …}}`. Фильтр видит ответ целиком, курсоры в `pagination` берутся из исходного ответа. Без фильтра ответ не оборачивается.
- **Результат:** ровно один результат фильтра возвращается как есть; несколько — JSON-массивом (`.results[] | {slug, title}` → `[{…}, {…}]`); ни одного — `[]`.
- **Ошибки.** Синтаксис и имена функций проверяются до запроса к API: неверный фильтр — ошибка `isError: true`, а запрос не отправляется. Если фильтр упал при выполнении, ошибка сообщает, что сам запрос к API выполнен: запрос, изменяющий данные, повторять не нужно.
- **Ответ не в JSON** (текст, пустое тело) возвращается без фильтра, с пояснением. У инструментов, которые сохраняют файл (`save_to`), и у составных инструментов аргумента `jq` нет; `api_request` с `jq` и `save_to` одновременно — ошибка.
- **Ограничения фильтра.** Длина — до 4096 байт. Недоступны окружение процесса (`env`, `$ENV`), входные потоки (`input`, `inputs`) и модули (`import`, `include`); `debug` и `stderr` ничего не выводят, `halt` — ошибка. Фильтр выполняется в отдельном процессе с пустым окружением и прерывается через 10 секунд: зацикленный или бесконечно рекурсивный фильтр возвращает ошибку и не влияет на сервер.

## Пользовательские инструменты

Частые запросы можно оформить именованными инструментами, чтобы агент не собирал их каждый раз заново: например, «подстраницы раздела команды». Пользовательский инструмент вызывает одну операцию Wiki API с фиксированными аргументами и необязательным фильтром `jq`. Инструменты описываются в TOML:

- `tools.toml` в каталоге конфигурации рядом с `profiles.toml` (`~/.config/wiki-mcp/tools.toml`; каталог можно переопределить переменной `WIKI_MCP_CONFIG_DIR`, на Linux учитывается `XDG_CONFIG_HOME`, в Windows — `%APPDATA%`) — читается при каждом запуске `serve`, если файл есть;
- другие файлы — только явно, флагом `serve --tools-file <путь>` (можно повторять). Файл из репозитория проекта — недоверенный ввод, поэтому клонирование репозитория само по себе инструментов не добавляет.

В [HTTP-режиме](http.md) читаются только файлы из `--tools-file` — на машине сервера при запуске; инструмент вызывается с токеном агента из запроса. Инструменты над операциями с локальными файлами там не регистрируются.

```toml
[[tools]]
name = "team_pages"
description = "Pages of the team section: slug and title only"
operation = "list_page_descendants"
jq = ".results[] | {slug, title}"

[tools.args]
slug = "team/project"
page_size = 50

[[tools]]
name = "comment_on_release_page"
description = "Add a comment to the release notes page"
operation = "create_comment"
args = { idx = 42 }
```

| Поле | Назначение |
| --- | --- |
| `name` | Имя инструмента: строчные латинские буквы, цифры и `_`, начинается с буквы, до 64 символов. |
| `description` | Описание для агента (обязательно). Сервер дополняет его операцией, фиксированными аргументами и ссылкой на справочник. |
| `operation` | Имя инструмента операции API (`get_page`, `list_page_descendants`, `create_comment`; найти — `api_search`). Составные инструменты (`upload_attachment`, `wait_for_operation`) операциями не являются и не подходят. |
| `args` | Фиксированные аргументы операции (TOML-таблица): параметры пути и запроса с именами из API и `body` целиком. Значения проверяются по схеме операции. |
| `jq` | [Фильтр ответа](#фильтр-ответа-jq), который применяется всегда. |

Фиксированные аргументы убираются из схемы инструмента: агент передаёт только остальные аргументы операции, а попытка передать фиксированный — ошибка. Нельзя фиксировать `save_to` и файловые аргументы (пути проверяются при каждом вызове), а также `null`. Кроме аргументов операции, пользовательский инструмент принимает `jq`: фильтр из вызова применяется после фильтра из файла (`(фильтр файла) | (фильтр вызова)`), а курсоры постраничной выдачи остаются в `pagination`.

Уровень доступа и аннотации инструмента — как у его операции; инструменты выше уровня сервера не регистрируются, а вызов такого инструмента объясняет, какой флаг нужен. Наборы инструментов (`--toolsets`) пользовательские инструменты не ограничивают; с `--dynamic-toolsets` они регистрируются сразу при запуске, без `enable_toolset`.

Ошибки в файле останавливают запуск сервера с понятным сообщением (файл и инструмент): неверный TOML, неизвестные поля, неизвестная операция или аргумент, неверный фильтр. Имя, совпадающее со встроенным инструментом (с любой операцией API, составным инструментом, `api_request`, `api_search`, `list_toolsets`, `enable_toolset`, `disable_toolset`) или с другим пользовательским инструментом, — тоже ошибка запуска, а не тихий пропуск. Проверить файлы заранее можно командой [`wiki-mcp tools check`](cli.md#tools).

## Составные инструменты

### upload_attachment

Загружает локальный файл и прикрепляет его к странице одним вызовом. Аргументы: `idx` — id страницы, `file` — путь к файлу, `file_name` — имя вложения (по умолчанию имя файла).

Шаги: `create_upload_session` (имя и точный размер файла) → `upload_file_part` (файл до 16 МиБ — одной частью, больший — частями по 16 МиБ) → `finish_upload_session` → `attach_uploaded_files`. Если шаг после создания сессии не удался, сессия отменяется (`abort_upload_session`), а ошибка называет шаг; ничего не прикрепляется. Повторный вызов прикрепляет ещё одну копию файла. Файл больше 16 МиБ загружается только в хранилища, которые принимают файл частями; для остальных сессия отменяется с понятной ошибкой.

Результат — ответ `attach_uploaded_files` (вложение с `download_url`) и сведения о загрузке (`upload`: id сессии, имя, размер, число частей). В тексте страницы вложение само не появляется: допишите `{% file src="<download_url>" name="<имя>" %}` через `append_page_content`.

Файл читает сервер с диска: содержимое не проходит через контекст агента. Путь должен быть внутри [разрешённых каталогов](security.md#локальные-файлы). Уровень — запись, набор — `attachments`; в HTTP-режиме инструмента нет, вместо него — [`create_upload_url`](#create_upload_url).

### create_upload_url

Только в [HTTP-режиме](http.md#загрузка-файлов): сервер работает не на машине агента и его файлы не читает, а передавать файл в аргументах (base64) — значит гнать его через контекст агента. Инструмент создаёт одноразовый адрес на этом же HTTP-сервере, на который агент отправляет файл сам командой `curl`; сервер потоком загружает его в Wiki и прикрепляет к странице.

Аргументы: `idx` — id страницы, `file_name` — имя вложения (только имя, без каталогов), `file_size` — точный размер файла в байтах (не больше 1 ГиБ), `expires_in_seconds` — сколько адрес ждёт начала загрузки (по умолчанию 300, не больше 900). Инструмент сразу проверяет, что страница есть (`get_page_by_id`), и возвращает:

```json
{
  "upload_url": "http://127.0.0.1:8767/uploads/<id>/<секрет>",
  "method": "PUT",
  "expires_in_seconds": 300,
  "idx": 42,
  "file_name": "report.pdf",
  "file_size": 52428800,
  "headers": {"Authorization": "…", "X-Org-Id": "<ID организации>"},
  "curl": "curl -sS -T <file> -H \"Authorization: $WIKI_AUTHORIZATION\" -H 'X-Org-Id: <ID организации>' 'http://127.0.0.1:8767/uploads/<id>/<секрет>'",
  "note": "…"
}
```

Агент подставляет вместо `<file>` путь к файлу и запускает команду. Токена в адресе и в команде нет: `$WIKI_AUTHORIZATION` — значение заголовка `Authorization`, которое отправляет MCP-клиент (`OAuth <токен>`), его подставляет оболочка из переменной окружения. Заголовка организации в команде нет, если сервер закреплён за организацией (`--org-id`, `--cloud-org-id`). Вместо `-T` (PUT) можно отправить файл `POST`-ом: `--data-binary @<file>`.

Приняв файл, сервер выполняет те же шаги, что `upload_attachment`: сессия загрузки, части по 16 МиБ, завершение, прикрепление; при ошибке сессия отменяется. Ответ на `curl` — JSON: при успехе ответ `attach_uploaded_files` (вложение с `download_url`) и `upload`, при ошибке — `{"error": "...", "message": "..."}`:

| Код | Причина |
| --- | --- |
| `200` | Файл прикреплён. |
| `400` | Тело меньше `file_size` или оборвалось; нет организации. |
| `401` | Нет заголовка `Authorization`. |
| `403` | Чужой `Host` или `Origin`; другой токен или другая организация, чем у MCP-запроса, создавшего адрес. |
| `404` | Адреса нет или секрет неверный. |
| `409` | На этот адрес файл уже загружается. |
| `410` | Адрес уже использован или его срок истёк: создайте новый. |
| `413` | Тело больше `file_size`. |
| `502` | Ошибка шага Wiki API; сессия загрузки отменена. |

Адрес одноразовый: после первой принятой отправки он больше не работает, даже если загрузка не удалась. Отправки, отклонённые до приёма (`401`, `403`, `404`, `413` и `400` по `Content-Length`), адрес не тратят. Активных адресов (не использованных и загружаемых) не больше 8. Уровень — запись, набор — `attachments`; в stdio-режиме инструмента нет, там файл загружает `upload_attachment`. Как защищён адрес — в [безопасности](security.md#одноразовые-адреса-загрузки).

### wait_for_operation

Копирование страницы (`clone_page`), копирование таблицы (`clone_grid`) и перенос страниц (`move_page`) выполняются фоном: ответ содержит `operation.type` и `operation.id`. `wait_for_operation` с `operation_type` (`clone`, `clone_inline_grid` или `move`) и `operation_id` опрашивает подходящий `get_*_operation_status` с растущим интервалом, пока статус не станет `success` или `failed`, но не дольше `timeout_seconds` (по умолчанию 30, не больше 120).

`success` — ответ статуса; `failed` — ошибка инструмента с ответом статуса. После тайм-аута операция продолжается фоном: вызовите инструмент снова, а не повторяйте операцию. Некоторые клиенты перестают ждать инструмент примерно через минуту, поэтому большой `timeout_seconds` не нужен. Уровень — чтение, набор — `pages`.

## api_search и api_request

Два инструмента регистрируются всегда, независимо от `--toolsets` и `--dynamic-toolsets`:

- `api_search` ищет по всем операциям спецификации и составным инструментам, в том числе выключенным: по имени, описанию, пути и набору. Запрос можно писать по-английски и по-русски («загрузить файл», «таблица», `grid rows`, `/v1/pages/{idx}/comments`). В каждом результате — имя инструмента, метод, путь, уровень доступа, набор, обязательные параметры, ссылка на справочник, зарегистрирован ли инструмент и, если нет, каким флагом его включить (`--allow-write`, `--allow-destructive`, `--toolsets <набор>`); составные инструменты — отдельным списком `composite_tools`. Аргумент `tool_name` возвращает полную схему аргументов одной операции; `toolset` ограничивает поиск набором; `limit` — число результатов. В API инструмент не обращается и всегда только читает.
- `api_request` отправляет запрос к любому пути Wiki API: `method`, `path` (с версией: `/v1/…`), `query` (объект; массив передаётся повторением ключа), `body` (JSON), `save_to` для скачивания файлов и `jq` для [фильтра ответа](#фильтр-ответа-jq). Заголовки задать нельзя: токен и организацию добавляет сервер. Полные URL, `?`, `#`, `..` и пути без версии отклоняются. Тело — только JSON: часть файла загружается своим инструментом.

Уровень доступа `api_request` определяется по спецификации: запрос сопоставляется с шаблонами путей операций (литеральные сегменты без учёта регистра и после percent-раскодирования), и действует уровень совпавшей операции — при нескольких совпадениях максимальный. Поэтому поиск через `POST /v1/search` работает на сервере только для чтения, а изменение прав доступа через `POST` требует `--allow-destructive`. Путь, которого нет в спецификации, оценивается по методу: `GET` — чтение, `DELETE` — удаление, остальные — запись. Запрос выше уровня сервера не отправляется: агент получает ошибку с флагом, который нужен.

Аннотации `api_request` соответствуют уровню сервера: `readOnlyHint` в режиме чтения, `destructiveHint` с `--allow-destructive`. `save_to` принимается только для операций, которые возвращают файл (содержимое и превью вложений), и для них обязателен: JSON-ответ в файл не сохраняется, он возвращается в результате с теми же заменами учётных данных.

## Локальные файлы

`upload_attachment` и `upload_file_part` принимают в аргументе `file` путь к файлу, а инструменты, которые возвращают файл (`download_attachment`, `download_attachment_by_url`, `download_attachment_preview`, `api_request` для таких операций), сохраняют его по пути из `save_to`. Пути должны быть внутри разрешённых каталогов: рабочего каталога сервера, системного временного каталога и каталогов из `--allow-path` ([подробнее](security.md#локальные-файлы)). `upload_file_part` отправляет файл целиком как одну часть (от 1 байта до 16 МиБ). В [HTTP-режиме](http.md#отличия-от-stdio) эти инструменты не регистрируются.

## Инструкции сервера

При подключении сервер передаёт агенту инструкции: уровень доступа и включённые наборы (с `--dynamic-toolsets` — как включать наборы), как адресовать страницы (slug или `idx`), как устроены аргументы, постраничная выдача и фильтр `jq`, что такое пользовательские инструменты (если они есть), как ждать фоновые операции, как найти выключенную операцию, что делать с большими ответами, какие каталоги разрешены для файлов и как приложить файл одним вызовом (в HTTP-режиме — через `create_upload_url`), что токен никогда не передаётся в аргументах и не запрашивается в чате и что делать при `401` и `403`. Отдельно сказано не переносить персональные данные из ответов (имена, логины, комментарии, тексты страниц) в логи, коммиты, код, тестовые данные, другие страницы и системы без просьбы пользователя.
