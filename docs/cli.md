# Справочник CLI

```text
wiki-mcp <команда> [флаги]
```

| Команда | Назначение |
| --- | --- |
| [`connect`](#connect) | Подключить сервер к Claude Code или Codex одной командой. |
| [`serve`](#serve) | Запустить MCP-сервер через stdio или по HTTP ([`--http`](#serve---http)). |
| [`auth`](#auth) | Управлять токенами и организациями профилей: `login`, `status`, `logout`. |

`wiki-mcp --version` печатает версию, `wiki-mcp <команда> --help` — справку по команде.

## Профили

Профиль — имя, под которым хранятся токен и настройки одного клиента. Профиль по умолчанию для `serve` и `auth` — `default`, другой выбирается флагом `--profile`; `connect` по умолчанию называет профиль по имени клиента.

- **Токен** — только в системном хранилище: macOS Keychain, Secret Service в Linux, Credential Manager в Windows. Сервис `dev.filipov.wiki-mcp`, учётная запись — имя профиля. Из переменных окружения и `.env` токен не читается, в `profiles.toml` не пишется и не печатается ни одной командой.
- **Настройки** (без токена) — в `~/.config/wiki-mcp/profiles.toml`; в Linux учитывается `XDG_CONFIG_HOME`, в Windows файл лежит в `%APPDATA%\wiki-mcp\profiles.toml`. Файл создают `connect` и `auth login`:

  ```toml
  [profiles.default]
  client = "codex"           # клиент, в котором профиль зарегистрирован через connect
  client_id = "<ClientID>"   # OAuth-приложение пользователя, необязательно
  token_type = "oauth"       # или "iam"
  allow_write = false
  allow_destructive = false
  toolsets = []

  [profiles.default.org]
  type = "yandex360"         # или "cloud"
  id = "<ID организации>"
  ```

Организация обязательна: Wiki принимает запросы только с её ID. Тип определяет заголовок:

| `type` | Организация | Заголовок |
| --- | --- | --- |
| `yandex360` | Yandex 360 для бизнеса | `X-Org-Id` |
| `cloud` | Yandex Cloud Organization | `X-Cloud-Org-Id` |

ID организации показан в панели администратора Yandex 360 (для Yandex 360) или в консоли Yandex Cloud Organization (для Yandex Cloud). ID — 1–64 символа из `A-Z`, `a-z`, `0-9`, `-`, `_`.

Тип токена (`token_type`) определяет схему заголовка `Authorization`:

| `token_type` | Токен | Заголовок |
| --- | --- | --- |
| `oauth` (по умолчанию) | OAuth-токен Яндекса | `Authorization: OAuth <токен>` |
| `iam` | IAM-токен Yandex Cloud, живёт не больше 12 часов | `Authorization: Bearer <токен>` |

`allow_destructive = true` подразумевает запись: при сохранении профиля `allow_write` выставляется тоже. Пустой `toolsets` — наборы по умолчанию.

Имя профиля: 1–64 символа из `A-Z`, `a-z`, `0-9`, `.`, `_`, `-`, не начинается с `-`.

### Linux без Secret Service

Запасного файлового хранилища нет. Если в сессии нет демона Secret Service (`org.freedesktop.secrets` на сессионной шине D-Bus), команды `auth` завершаются ошибкой с подсказкой. Запустите демон хранилища: GNOME Keyring, KDE Wallet или KeePassXC с интеграцией Secret Service. На машине без графической сессии можно поднять шину и разблокированное хранилище вручную:

```bash
dbus-run-session -- sh
# внутри новой оболочки; пароль хранилища читается из stdin
gnome-keyring-daemon --unlock --components=secrets
```

Или используйте [HTTP-режим](http.md): там хранилище не нужно.

## connect

```text
wiki-mcp connect <claude-code|codex> [флаги]
```

Подключает сервер к MCP-клиенту: создаёт или обновляет профиль, получает и сохраняет токен и после подтверждения добавляет сервер в конфигурацию клиента. Токен не проходит через агента и не попадает в конфигурацию клиента: туда записывается только команда

```text
<путь к wiki-mcp> serve --profile <профиль> [--allow-write] [--allow-destructive] [--toolsets <a,b>|all]
```

| Флаг | По умолчанию | Назначение |
| --- | --- | --- |
| `--profile <имя>` | имя клиента (`claude-code`, `codex`) | Профиль. |
| `--name <имя>` | `wiki` | Имя сервера в конфигурации клиента. |
| `--scope <user\|project>` | `user` | `user` — для всех проектов пользователя; `project` — в `.mcp.json` текущего каталога (только Claude Code). |
| `--allow-write` | выкл. | Разрешить инструменты записи. |
| `--allow-destructive` | выкл. | Разрешить инструменты удаления и изменения прав доступа; включает `--allow-write` (в профиль сохраняются оба флага). |
| `--toolsets <a,b,…>` | набор `serve` по умолчанию | Наборы инструментов через запятую или `all` — все наборы, включая те, что появятся в новых версиях; неизвестный набор — ошибка. |
| `--client-id <ID>` | из профиля | `ClientID` вашего OAuth-приложения (32 шестнадцатеричных символа). |
| `--org-id <ID>` | из профиля | ID организации Yandex 360 для бизнеса (`X-Org-Id`). |
| `--cloud-org-id <ID>` | из профиля | ID организации Yandex Cloud (`X-Cloud-Org-Id`). |
| `-y`, `--yes` | выкл. | Не задавать вопросов «да/нет»: оставить рабочий сохранённый токен и записать конфигурацию клиента. |
| `--skip-check` | выкл. | Сохранить токен без проверки запросом к API. |
| `--no-browser` | выкл. | Не открывать ссылки в браузере, только напечатать их. |

Шаги:

1. **OAuth-приложение.** Своего приложения в `wiki-mcp` нет: токен выдаёт ваше собственное приложение Яндекс OAuth. Если в профиле ещё нет `client_id` (и не передан `--client-id`), `connect` предлагает взять приложение, уже сохранённое в другом профиле, или открывает страницу создания приложения <https://oauth.yandex.ru/client/new/> и подсказывает настройки:
   - тип — «Для доступа к API или отладки»;
   - название — любое, например `wiki-mcp-<профиль>`, и контактная почта;
   - права — чтение Yandex Wiki (`wiki:read`), а для `--allow-write` и `--allow-destructive` также запись (`wiki:write`);
   - Redirect URI, если форма его спрашивает (платформа «Веб-сервисы»), — `https://oauth.yandex.ru/verification_code`.

   Затем спрашивает `ClientID` со страницы приложения, проверяет формат и сразу сохраняет его в профиль: повторный `connect` его больше не спрашивает. `ClientID` не секретный; Client secret не нужен. Если запись включается для профиля, приложение которого создано только с `wiki:read`, добавьте приложению право `wiki:write` и получите новый токен. Почему права лучше давать минимальные и по приложению на агента — в [OAuth-приложении и токене](oauth.md).
2. **Организация** — как в [`auth login`](#auth-login): флаг, профиль или вопрос о типе и ID.
3. **Токен.** Если в хранилище уже есть токен профиля и он проходит проверку, `connect` предлагает его оставить (с `--yes` — оставляет). Иначе открывает ссылку авторизации приложения `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>`: войдите в аккаунт, от имени которого будет работать агент, разрешите доступ и вставьте показанный токен в скрытый ввод. Токен проверяется запросом `GET /v1/users/me` и сохраняется в системное хранилище; если проверка не прошла, ничего не сохраняется. `connect` работает только с OAuth-токеном: тип токена профиля становится `oauth`, сохранённый IAM-токен не оставляется.
4. **Профиль.** В `profiles.toml` записываются клиент, `client_id`, тип токена, организация, флаги доступа и наборы инструментов из флагов `connect` (флаги доступа и наборы перезаписываются при каждом запуске).
5. **Конфигурация клиента.** `connect` показывает, что именно будет записано, и спрашивает подтверждение; при отказе (или без ответа) конфигурация не меняется, а токен и профиль остаются.
   - **Claude Code** — через его CLI: `claude mcp add --scope <scope> <имя> -- <путь> serve --profile <профиль> …`. Файлы Claude Code напрямую не правятся. Если сервер с таким именем уже есть и запускает `wiki-mcp`, он заменяется (`claude mcp remove` и снова `add`) после подтверждения.
   - **Codex** — таблица `[mcp_servers.<имя>]` в `$CODEX_HOME/config.toml` (по умолчанию `~/.codex/config.toml`):

     ```toml
     [mcp_servers.wiki]
     command = "/opt/homebrew/bin/wiki-mcp"
     args = ["serve", "--profile", "codex", "--allow-write"]
     ```

     Остальные записи, комментарии и форматирование файла сохраняются; запись с тем же именем заменяется на месте.

   Запись с тем же именем, которая запускает другой сервер, а не `wiki-mcp`, заменяется только после явного ответа в терминале; с `--yes` она не заменяется никогда. Чтобы подключить сервер рядом с ней, выберите другое имя через `--name`.

После подключения перезапустите клиент. В конфигурацию записывается абсолютный путь к запущенному бинарнику без раскрытия symlink: при установке через Homebrew путь `bin/wiki-mcp` переживает обновления.

Ссылки открываются в браузере по умолчанию. Браузер не открывается с `--no-browser`, по SSH и в Linux без графической сессии; ссылки печатаются всегда, их можно открыть на своём компьютере.

Для каждого клиента используйте отдельный профиль и отдельное OAuth-приложение, чтобы токен каждого можно было отозвать независимо.

## serve

```text
wiki-mcp serve [--profile <имя>] [--allow-write] [--allow-destructive]
               [--toolsets <набор,...>|all] [--allow-path <каталог>]...
               [--timeout <секунды>] [--max-response-bytes <байты>]
               [--log-level <уровень>] [--status]
```

Запускает MCP-сервер через stdio: MCP-клиент (Claude Code, Codex и другие) запускает команду сам и общается с ней через stdin и stdout. HTTP-режим описан ниже, в [`serve --http`](#serve---http). Каждая операция Wiki API из встроенной спецификации — отдельный инструмент; имя инструмента — короткое имя операции (`get_page`, `create_page`, `list_attachments`). Кроме них доступны составные инструменты `upload_attachment` и `wait_for_operation` и всегда — `api_search` (поиск по всем операциям) и `api_request` (запрос к любому пути API в пределах уровня доступа), см. [MCP-инструменты](tools.md).

Токен и организация берутся только из профиля (`--profile`, по умолчанию `default`): токен — из системного хранилища, его тип и организация — из `profiles.toml`. Если чего-то нет, сервер не запускается и подсказывает команду `auth login`. В аргументах инструментов токена нет.

| Флаг | Назначение |
| --- | --- |
| `--profile <имя>` | Профиль с токеном и организацией. |
| `--allow-write` | Регистрировать инструменты, которые создают и меняют данные. |
| `--allow-destructive` | Регистрировать и инструменты, которые удаляют данные или меняют права доступа; включает запись. |
| `--toolsets <набор,...>` | Наборы инструментов через запятую или `all`. |
| `--allow-path <каталог>` | Дополнительный каталог для локальных файлов; флаг повторяется. |
| `--timeout <секунды>` | Таймаут одного запроса к API, по умолчанию 60. |
| `--max-response-bytes <байты>` | Предел ответа API, который возвращается агенту, по умолчанию 262144 (256 КиБ). Больший ответ — ошибка с подсказкой сузить запрос. На скачивание файлов в `save_to` не распространяется. |
| `--log-level <уровень>` | Уровень или фильтр логов в stderr (`info`, `debug`, `wiki_mcp_core=debug`). Без флага — переменная `RUST_LOG`, без неё — `warn`. |
| `--status` | Показать действующие настройки и выйти, не запуская сервер. |

### Уровни доступа и наборы

Без флагов сервер работает только на чтение с наборами `pages`, `attachments`, `comments` и `grids`. Флаги командной строки важнее настроек профиля: без `--allow-write` и `--allow-destructive` уровень берётся из `allow_write` и `allow_destructive` профиля, без `--toolsets` — наборы из `toolsets` профиля. Наборы `access` (персональные права доступа к страницам) и `extra` (операции, которых нет в справочнике Wiki API) включаются только явно. Неизвестный набор — ошибка запуска со списком допустимых.

Что входит в уровни и наборы, как устроены аргументы и ответы инструментов, `api_search` и `api_request` — в [MCP-инструментах](tools.md). Вырезание учётных данных из ответов и правила для локальных файлов — в [Безопасности](security.md).

### serve --status

```text
wiki-mcp serve --status [--profile <имя>] [--allow-write] [--allow-destructive] [--toolsets ...] [--allow-path ...]
```

Печатает, с какими настройками запустился бы сервер с теми же флагами: профиль, сохранён ли токен (без значения), тип токена, организацию, уровень доступа и откуда он взят (флаги, профиль или по умолчанию), включённые и выключенные наборы, число инструментов, разрешённые каталоги и путь к `profiles.toml`. Сервер не запускается, к API запросов нет. Если не хватает токена или организации, команда подсказывает, как их сохранить.

### serve --http

```text
wiki-mcp serve --http [--listen <IP:порт>] [--allowed-host <имя>]... [--allowed-origin <origin>]...
                      [--org-id <ID> | --cloud-org-id <ID>] [--max-request-bytes <байты>]
                      [--allow-write] [--allow-destructive] [--toolsets <набор,...>|all]
                      [--timeout <секунды>] [--max-response-bytes <байты>] [--log-level <уровень>]
```

Запускает тот же сервер как HTTP-сервис (Streamable HTTP без сессий): `POST /mcp` и `GET /health`, по умолчанию на `127.0.0.1:8767`. Профилей и системного хранилища в этом режиме нет: каждый запрос агента несёт токен в `Authorization: OAuth <токен>` (или `Bearer <IAM-токен>`) и организацию в `X-Org-Id` или `X-Cloud-Org-Id`, если её не задаёт флаг сервера. Уровень доступа и наборы задаются только флагами, локальные файлы выключены; `--profile`, `--allow-path` и `--status` вместе с `--http` — ошибка.

| Флаг | Назначение |
| --- | --- |
| `--http` | Режим HTTP вместо stdio. |
| `--listen <IP:порт>` | Адрес и порт, по умолчанию `127.0.0.1:8767`. |
| `--allowed-host <имя>` | Дополнительное допустимое значение `Host` (`имя` или `имя:порт`); флаг повторяется. |
| `--allowed-origin <origin>` | Допустимый `Origin` браузерного клиента; флаг повторяется. |
| `--org-id <ID>` | Организация Yandex 360 для всех запросов; другая организация в запросе отклоняется. |
| `--cloud-org-id <ID>` | Организация Yandex Cloud для всех запросов; другая организация в запросе отклоняется. |
| `--max-request-bytes <байты>` | Предел тела запроса MCP, по умолчанию 1048576 (1 МиБ). |

Коды ответов, Docker-образ, `compose.yaml` и подключение клиентов — в [HTTP-режиме](http.md).

## auth

### auth login

```text
wiki-mcp auth login [--profile <имя>] [--org-id <ID> | --cloud-org-id <ID>]
                    [--token-type <oauth|iam>] [--token-stdin] [--skip-check]
```

Сохраняет токен Wiki и организацию профиля:

1. Организация: `--org-id` (Yandex 360) или `--cloud-org-id` (Yandex Cloud); без флагов берётся из профиля, а если её там нет — спрашивается тип и ID.
2. Тип токена: `--token-type oauth` (OAuth-токен, по умолчанию) или `--token-type iam` (IAM-токен Yandex Cloud); без флага — тип из профиля, иначе `oauth`.
3. Токен: скрытым вводом в терминале или, с `--token-stdin`, из stdin (например, из менеджера паролей). С `--token-stdin` организация не спрашивается: передайте флаг, если в профиле её ещё нет.
4. Проверка: запрос `GET /v1/users/me` с токеном и заголовком организации; печатается пользователь. `--skip-check` пропускает проверку (без сети).
5. Токен сохраняется в системное хранилище (заменяя прежний), тип токена и организация — в `profiles.toml`. Остальные настройки профиля не меняются; новый профиль создаётся с доступом только на чтение.

OAuth-токен выдаёт ваше собственное OAuth-приложение Яндекса с доступом к Wiki. Если в профиле есть `client_id`, команда печатает ссылку для получения токена; создать приложение и сохранить `client_id` помогает [`connect`](#connect). Для IAM-токена команда подсказывает `yc iam create-token`: такой токен живёт не больше 12 часов, после этого его нужно сохранить заново.

### auth status

```text
wiki-mcp auth status [--profile <имя>] [--skip-check]
```

Показывает профиль, сохранён ли токен (без значения), тип токена, организацию, пользователя, которому принадлежит токен, и организацию из ответа Wiki (запрос `GET /v1/users/me`; `--skip-check` — без запроса), `client_id`, клиент, в котором профиль зарегистрирован через `connect`, разрешены ли запись и удаление, наборы инструментов и путь к `profiles.toml`. Если проверка не прошла, причина печатается в строке `User`.

### auth logout

```text
wiki-mcp auth logout [--profile <имя>] [--forget]
```

Удаляет токен профиля из системного хранилища. С `--forget` также удаляет настройки профиля из `profiles.toml`. Если токен больше нигде не нужен, отзовите его ([отзыв токена](oauth.md#отзыв-токена)).

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `WIKI_MCP_CONFIG_DIR` | Каталог с `profiles.toml` вместо `~/.config/wiki-mcp`. |
| `CODEX_HOME` | Каталог конфигурации Codex для `connect codex` вместо `~/.codex`. |
| `RUST_LOG` | Уровень логов `serve` в stderr, если не задан `--log-level`. |

Токен Wiki из переменных окружения не читается никогда.
