# OAuth-приложение и токен

Wiki API принимает OAuth-токен Яндекса или IAM-токен Yandex Cloud. Своего OAuth-приложения в `wiki-mcp` нет: OAuth-токен выдаёт приложение, которое вы создаёте сами. Так права, срок жизни и отзыв токена полностью под вашим контролем, а в бинарнике нет чужого `ClientID`.

`connect` проводит через все шаги сам: открывает страницу создания приложения, подсказывает настройки, спрашивает `ClientID`, открывает ссылку получения токена и принимает токен скрытым вводом ([справочник `connect`](cli.md#connect)). Ниже — то же вручную и почему настройки именно такие.

## Создание приложения

1. Откройте <https://oauth.yandex.ru/client/new/> под аккаунтом, которому будет принадлежать приложение.
2. Тип — «Для доступа к API или отладки».
3. Название — любое, по которому приложение легко узнать и отозвать, например `wiki-mcp-codex`. Контактная почта — ваша.
4. Права Yandex Wiki:
   - чтение (`wiki:read`) — всегда;
   - запись (`wiki:write`) — только если агенту нужна запись (уровень записи или удаления профиля).
5. Если форма спрашивает Redirect URI (платформа «Веб-сервисы»), укажите `https://oauth.yandex.ru/verification_code`.
6. Сохраните приложение и скопируйте его `ClientID` (32 шестнадцатеричных символа). `ClientID` не секретный, Client secret не нужен.

`connect` сохраняет `ClientID` в профиль (`client_id` в `profiles.toml`), и при повторном запуске его больше не спрашивает. Передать его заранее можно флагом `--client-id`. Для нового профиля `connect` предлагает взять приложение, уже сохранённое в другом профиле, и сразу перейти к токену; но отдельное приложение на агента удобнее ([ниже](#приложение-на-каждого-агента)).

## Получение токена

Откройте ссылку авторизации приложения:

```text
https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>
```

Войдите в аккаунт, от имени которого будет работать агент, разрешите доступ и скопируйте показанный токен. Вставьте его в скрытый ввод `connect` или `auth login`: токен проверяется запросом `GET /v1/users/me` и сохраняется в системное хранилище. Ни в конфигурацию клиента, ни в файлы, ни в переменные окружения он не попадает.

Агент работает с правами пользователя токена: Wiki покажет ему только те страницы, которые видит этот пользователь, а изменения будут сделаны от его имени. Если агентам не нужен доступ ко всему, что видите вы, заведите для них отдельного пользователя организации с нужными правами в Wiki и получайте токен под ним.

Токену нужна [организация](cli.md#профили): ID организации Yandex 360 для бизнеса (`X-Org-Id`) или Yandex Cloud Organization (`X-Cloud-Org-Id`). Её спрашивают `connect` и `auth login`.

## Права приложения

Права токена — это права приложения на момент получения токена. Сервер тоже ограничивает агента (по умолчанию только чтение), но это ограничение программы, а не токена:

- **Сервер только на чтение не делает токен безопасным.** Токен с `wiki:write` позволяет менять и удалять страницы любым способом: если он утечёт (из логов, из буфера обмена, через агента с доступом к оболочке, из конфигурации HTTP-клиента), им можно писать в обход сервера. Токен только с `wiki:read` при утечке позволяет только читать.
- **В HTTP-режиме токен виден агенту** в конфигурации клиента, поэтому там права токена — единственная настоящая граница ([модель угроз](http.md#модель-угроз)).

Поэтому агенту, которому достаточно чтения, давайте токен приложения только с `wiki:read`, а `wiki:write` добавляйте только тем, кто действительно создаёт и меняет страницы.

Чтобы расширить права (например, включить запись для агента, который раньше только читал), добавьте приложению право записи в Wiki на <https://oauth.yandex.ru/> и получите новый токен: у уже выданного токена остаются прежние права. Затем сохраните его и поднимите уровень профиля: `wiki-mcp connect <клиент> --allow-write` (или `wiki-mcp auth login --profile <профиль>` и `wiki-mcp ui`).

## Приложение на каждого агента

Создавайте отдельное приложение и токен для каждого клиента (Claude Code, Codex, CI, HTTP-сервер для команды) и храните их в отдельных профилях:

- токен любого агента можно отозвать, не затрагивая остальных;
- права настраиваются под каждого: одному только чтение, другому запись;
- в списке приложений с доступом к аккаунту сразу видно, какое из них какому агенту принадлежит.

`connect` по умолчанию создаёт профиль с именем клиента (`claude-code`, `codex`) и предлагает назвать приложение `wiki-mcp-<профиль>`.

## IAM-токен Yandex Cloud

Федеративные и сервисные аккаунты Yandex Cloud работают с Wiki по IAM-токену. Сервер отправляет его как `Authorization: Bearer <токен>`, а OAuth-токен — как `Authorization: OAuth <токен>`; тип сохраняется в профиле (`token_type`). IAM-токен живёт не больше 12 часов, поэтому профиль может получать токены сам и обновлять их до истечения срока — через `yc iam create-token` или по ключу сервисного аккаунта, без OAuth-приложения. Как это настроить — в [IAM-токенах](iam.md).

Можно и сохранить готовый IAM-токен вручную: `wiki-mcp auth login --profile <профиль> --token-type iam`. Через 12 часов его придётся сохранить заново.

## Отзыв токена

- Удалите токен из хранилища: `wiki-mcp auth logout --profile <профиль>` (с `--forget` — и настройки профиля).
- Отзовите сам токен: отзовите доступ приложения в настройках Яндекс ID (список приложений, у которых есть доступ к аккаунту) или удалите приложение на <https://oauth.yandex.ru/>. Удаление из хранилища не отзывает токен: если он мог утечь, отзывайте обязательно.

Когда токен истечёт или будет отозван, Wiki ответит `401`, а агент предложит выполнить `wiki-mcp auth login --profile <профиль>`.
