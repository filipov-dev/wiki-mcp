# wiki-mcp

MCP-сервер и CLI для [Yandex Wiki Public API](https://yandex.ru/support/wiki/ru/api-ref/). Даёт Claude Code, Codex и другим MCP-клиентам читать, создавать и править страницы Wiki, дописывать текст в разделы, прикладывать и скачивать файлы, комментировать, работать с динамическими таблицами, копировать и восстанавливать страницы.

- **Все операции API — MCP-инструменты.** Они генерируются при сборке из официальной OpenAPI-спецификации Wiki API с дополнением (короткие имена, уровни доступа, описания из справочника); `api_search` находит нужную операцию, `api_request` вызывает любую в пределах уровня доступа.
- **Составные инструменты.** `upload_attachment` загружает локальный файл вложением страницы одним вызовом (сессия загрузки, части, прикрепление), `wait_for_operation` дожидается фонового копирования или переноса страниц. В HTTP-режиме файл загружается через одноразовый адрес `create_upload_url` и `curl`.
- **Короткие ответы и свои инструменты.** Фильтр `jq` оставляет из ответа только нужное, а в `tools.toml` можно описать свои инструменты поверх операций API с фиксированными аргументами.
- **Токен — только в системном хранилище** (macOS Keychain, Secret Service в Linux, Credential Manager в Windows), отдельный профиль и токен для каждого агента. OAuth-токен выдаёт ваше собственное OAuth-приложение Яндекса; ни переменные окружения, ни `.env`, ни конфигурация клиента его не содержат. Исключение — HTTP-режим (ниже): там токен агента приходит в заголовке каждого запроса и сервер его не хранит.
- **По умолчанию только чтение.** Запись и удаление включаются в настройках профиля; инструменты выше разрешённого уровня агенту не видны. На macOS права сверх чтения действуют только после одобрения владельцем через Touch ID или пароль.
- **Консоль и TUI.** `wiki-mcp call` вызывает любой инструмент из терминала с правами профиля, `wiki-mcp ui` показывает профили, их права, регистрации в клиентах и то, что видно токену в Wiki.
- **Учётные данные не попадают к агенту.** Токены, пароли и ключи в ответах Wiki, в том числе в тексте страниц и ячейках таблиц, заменяются на `[redacted]`.

Сервер работает через stdio: MCP-клиент сам запускает `wiki-mcp serve`. Для Linux-машин без системного хранилища и клиентов, которые подключаются по адресу, есть [HTTP-режим](docs/http.md) (`serve --http`, в том числе в Docker).

## Установка

### Установочный скрипт (Linux и macOS)

```bash
curl -fsSL https://codeload.github.com/filipov-dev/wiki-mcp/tar.gz/refs/heads/install | tar -xzO | sh
```

Скрипт ставит последнюю версию в `~/.local/bin` без `sudo` и сверяет архив с `SHA256SUMS` релиза; повторный запуск обновляет бинарник. Параметры (`--version`, `--prefix`) — в [docs/install.md](docs/install.md#установочный-скрипт).

### Homebrew (macOS и Linux)

```bash
brew tap filipov-dev/tap https://git.sourcecraft.dev/filipov-dev/homebrew-tap.git
brew install filipov-dev/tap/wiki-mcp
```

Tap размещён на SourceCraft, поэтому `brew tap` нужен полный адрес. Устанавливайте формулу по полному имени `filipov-dev/tap/wiki-mcp`.

### Готовый архив

Архивы для macOS (универсальный, подписан и нотаризован), Linux x86_64 и aarch64 (статические, без зависимостей), Windows x86_64 (`.zip`, без зависимостей, не подписан) и `SHA256SUMS` — на [странице релизов на GitHub](https://github.com/filipov-dev/wiki-mcp/releases) (код — в [SourceCraft](https://sourcecraft.dev/filipov-dev/wiki-mcp) и в его копии на GitHub). Установка в Windows — [docs/install.md](docs/install.md#windows).

### Из исходников

```bash
cargo build --release
```

Бинарник: `target/release/wiki-mcp`. Нужен Rust 1.88 или новее и C-компилятор.

Подробнее, включая проверку контрольных сумм, обновление и удаление: [docs/install.md](docs/install.md).

## Быстрый старт: Claude Code и Codex

```bash
wiki-mcp connect claude-code
# или
wiki-mcp connect codex
```

`connect` поможет создать собственное OAuth-приложение Яндекса (откроет форму и подскажет настройки), спросит организацию (Yandex 360 или Yandex Cloud), откроет ссылку получения токена, примет токен скрытым вводом, проверит его и сохранит в системное хранилище под профилем с именем клиента. Затем покажет, что изменится в конфигурации клиента, и после подтверждения зарегистрирует сервер `wiki`. Перезапустите клиент.

Права можно задать сразу при подключении: они сохраняются в профиль, а не в команду запуска сервера ([уровни доступа](#уровни-доступа)):

```bash
wiki-mcp connect codex --allow-write
```

Агенту, которому достаточно чтения, создайте приложение только с правом `wiki:read`: даже если сервер работает только на чтение, токен с правом записи опасен при утечке. Подробнее: [docs/oauth.md](docs/oauth.md).

Федеративные и сервисные аккаунты Yandex Cloud подключаются без OAuth-приложения: сервер сам получает IAM-токены через `yc iam create-token` или по ключу сервисного аккаунта (ключ хранится в системном хранилище) и обновляет их до истечения срока.

```bash
wiki-mcp connect codex --service-account-key key.json --cloud-org-id <ID организации>
wiki-mcp connect claude-code --iam-source yc --cloud-org-id <ID организации>
```

Подробнее: [docs/iam.md](docs/iam.md).

## Другие MCP-клиенты

`connect` настраивает только Claude Code и Codex. Любой другой клиент со stdio-серверами подключается вручную:

1. Сохраните токен и организацию в отдельный профиль: `wiki-mcp auth login --profile cursor`.
2. Зарегистрируйте в клиенте stdio-сервер с командой `wiki-mcp` и аргументами `serve --profile <профиль>`:

   ```json
   {
     "mcpServers": {
       "wiki": {
         "command": "/opt/homebrew/bin/wiki-mcp",
         "args": ["serve", "--profile", "cursor"]
       }
     }
   }
   ```

   Укажите в `command` абсолютный путь из `command -v wiki-mcp`. Запись или удаление разрешаются в профиле ([уровни доступа](#уровни-доступа)), а не в `args`.

Пути к конфигурации и особенности Google Antigravity, Kimi Code и ZCode — в [docs/clients.md](docs/clients.md#google-antigravity).

## HTTP-режим

```bash
docker compose up --build -d   # или: wiki-mcp serve --http
claude mcp add --transport http wiki http://127.0.0.1:8767/mcp \
  --header "Authorization: OAuth <токен>" \
  --header "X-Org-Id: <ID организации>"
```

Сервер ничего не хранит: токен и организация приходят в каждом запросе, токен уходит только в Wiki API. Токен виден агенту в конфигурации клиента, поэтому граница безопасности здесь — права токена, а флаги доступа сервера (`--allow-write`, `--allow-destructive`; профили здесь не используются) — страховка от ошибок. Локальные файлы в HTTP-режиме выключены: файл агент отправляет `curl`-ом на одноразовый адрес из `create_upload_url`, токен в адрес не входит и сервером не хранится. Подробнее: [docs/http.md](docs/http.md).

## Уровни доступа

| Уровень | В профиле | Что доступно |
| --- | --- | --- |
| Чтение | по умолчанию | Только инструменты, которые читают данные, в том числе поиск по Wiki и скачивание вложений. |
| Запись | `allow_write = true` | Создание и изменение: страницы, текст, комментарии, таблицы, загрузка файлов, копирование, перенос и восстановление страниц. |
| Удаление | `allow_destructive = true` (включает запись) | Удаление страниц, вложений, комментариев, таблиц и изменение прав доступа к страницам. |

Уровень доступа и дополнительные каталоги для файлов (`allow_path`) — настройки профиля. Их меняет `wiki-mcp ui` (вкладка Access: клавиши `r`, `w`, `d`, затем `s`) или `connect` с флагом:

```bash
wiki-mcp connect claude-code --allow-write
```

В конфигурацию клиента флаги доступа не попадают: клиент запускает `serve --profile <имя>`, а `serve` берёт права из профиля. Флаги `serve` (`--allow-write`, `--allow-destructive`, `--allow-path`) могут только сузить права профиля. На macOS права сверх чтения нужно одобрить: при сохранении `ui` и `connect` спрашивают Touch ID или пароль пользователя macOS, а без одобрения сервер работает только на чтение и пишет об этом в stderr. Так агент, который может править файлы, не расширит себе права правкой `profiles.toml` или конфигурации клиента. В Linux и Windows одобрения нет: границу задают права токена в Wiki. Регистрации старых версий с флагами доступа продолжают запускаться; `connect` перерегистрирует их без флагов. Подробнее: [docs/security.md](docs/security.md#уровни-доступа).

Инструменты выше разрешённого уровня не регистрируются: агент их не видит и не может вызвать. `--toolsets` выбирает разделы API: по умолчанию включены страницы, вложения, комментарии и таблицы (`pages`, `attachments`, `comments`, `grids`); права доступа к страницам (`access`) и операции, которых нет в справочнике (`extra`: перенос страниц, история версий, обратные ссылки), включаются явно, `--toolsets all` включает все. С `--dynamic-toolsets` агент сам включает нужные разделы по ходу работы, а список инструментов в контексте остаётся коротким.

Ответы можно сокращать фильтром `jq` (аргумент любого инструмента API, например `.results[] | {slug, title}`), а частые запросы — оформить своими инструментами в `~/.config/wiki-mcp/tools.toml`. Подробнее: [docs/tools.md](docs/tools.md).

## Консоль и TUI

```bash
wiki-mcp call                                   # инструменты, доступные профилю
wiki-mcp call get_page slug=users/name/page fields=content
wiki-mcp call get_page --schema                 # схема аргументов
wiki-mcp ui                                     # профили, права, регистрации, токен
```

`call` собирает сервер с теми же правами, что и `serve`, и вызывает его в этом же процессе: проверка аргументов, уровни доступа и вырезание учётных данных те же, что у агента. Инструменты уровня удаления спрашивают подтверждение (`--yes` — без вопроса). Подробнее: [docs/cli.md](docs/cli.md#call).
